# 朗读子系统 · 架构决定与代价

> 本文记录 ColorReader 朗读（`useReadAloud` + `tts.ts` + `edge.ts` + `timeStretch.ts` + `mini_bar.rs`）**为什么是现在这个样子**——每条决定连同它的代价，以及「不这么做会怎样」。
> 这些决定散落在代码注释、commit 正文和各自的 PR 里。本文把它们收在一处，因为**它们互相约束**：单看一条会像可以「优化」回去，看全了才知道哪根钉子是承重的。
>
> 涉及的文件与行号基于 2026-10-04 的 `main`（`b61abe4`）。**参考 readest，但禁复制其代码**（项目纪律）——本文提到的 readest 行为均已独立复核到行，且我们的实现是照公开算法自己写的。

                    │     ↕  stores/speech.ts（会话接缝，不持久化）        │

四条独立的决定撑住这个形状：**会话住在外壳**（§2）、**窗口不在了仍能回来**（§3）、**合成钉 1.0×**（§4）、**变速在播放侧**（§5）。它们各自都有一笔代价列在后面。

## 1. 两条引擎，只有一种读者的行为

`src/features/reader/tts.ts` 是读者的控件**唯一**说话的地方，也是唯一知道「引擎不止一个」的模块：

| 引擎                             | 合成在哪               | 倍速怎么生效                                | 覆盖         |
| -------------------------------- | ---------------------- | ------------------------------------------- | ------------ |
| **Edge TTS**（默认音色 Yunjian） | 联网，服务端 WebSocket | 播放侧 WSOLA 拉伸（§5）                     | 全部音色     |
| 系统 `speechSynthesis`           | 平台本地               | `utterance.rate`，只在 `speak()` 那一刻有效 | 平台有的那些 |

**代价：系统语音这条路的倍速只能在下一句生效。** 这是平台限制不是我们的选择——`utterance.rate` 在 `speak()` 之后没有可改的接口。readest 同样这么做（它的 `WebSpeechClient.ts:37` 仍是 `utterance.rate = getRate()`）。

**但只有「生效于哪一句」这一条允许不同。** 「切倍速要重新合成」这种*代价*不允许不同——那不是引擎的能力差异，是我们自己制造的。§5 就是为它存在的。

## 2. 会话住在外壳，不住在阅读页

**决定**：`useTts` 与播放器都挂在 `TtsHost`（`AppShell` 之下），`stores/speech.ts` 是接缝。阅读页只**借**一个 `SpeechTransport`，页面卸载时还回去，语音不停。

**为什么**：朗读玩家原来在 `ReaderPage` 里，随页面一起死。而「一边听着书、一边在书架上找下一本」是这类读者的常态。引擎 + 播放器搬出去之后，`SpeechCard`（卡片）与 `ttsParts`（胶囊与卡片共用的零件）才能在第二个窗口里复用同一份实现。

**会话状态不进持久化**——它是「此刻正在发声的嗓音」，不是偏好。值得留下的 `speechRate` / `speechVoiceURI` 在 `useReaderSettings` 里。

**接缝上有一处不对称是刻意的**：阅读页在屏时它把 transport **借**给外壳，播放器就不驱动引擎；阅读页不在时 `controls` 是 `null`，播放器自己驱动。所以「谁在推引擎」有两个来源，而 `stores/speech.ts` 的注释必须写明这一点——读代码时最容易在这里绕进去。

**代价：多一个 store、且它不持久化**。这是「在书架上继续听」与「重开 app 立刻续播」之间选的**后者不做**。做的话要把队列、位置、引擎指针一起序列化，而队列是按 `chapterIdx` 对齐的——书一旦被重新导入，对齐关系就断了。

## 3. 窗口不在了，会话仍能回来（三条路）

**决定**：主窗口的关闭事件改成**隐藏**而不是退出（`lib.rs:214-220`），配合：

| 路            | 实现                                                               | 为什么需要它                                                  |
| ------------- | ------------------------------------------------------------------ | ------------------------------------------------------------- |
| **托盘**      | `install_tray`，左键也开菜单（菜单栏图标上左键才是读者会按的那个） | 窗口已隐藏时，Dock 图标还在但点不出窗口；托盘是唯一还在的入口 |
| **悬浮条**    | 第二个 Tauri 窗口 `label=mini`，透明 / 置顶 / 贴屏幕底边           | 给「已经最小化、就想换一句」一个不离开阅读姿势的位置          |
| **Dock 唤回** | `RunEvent::Reopen` → `reveal_window`                               | macOS 特有：隐藏 ≠ 关闭，没有这一条 app 就「开着但摸不到」    |

托盘菜单里**只有两条**能在后端直接做完（显示窗口、退出）。播放/暂停/上一句/下一句/停止都**需要会话**——而队列、位置、引擎指针是前端状态，前端恰好是这个菜单在用时不可见的东西。所以它们以 `TRAY_CONTROL_EVENT`（`"tts://control"`）转发，由**当时握着 transport 的那个 `TtsPlayer`** 执行。

**代价：一个事件名跨了两侧**。`TRAY_CONTROL_EVENT` 在 Rust 和 TS 里各写了一份字面量，两边必须手改同时。**加一项托盘控制要改两个地方**，漏一个就是菜单里有个不响的按钮（不报错）。

**五档定高是量出来的，不是猜的**（`mini_bar.rs:147-165`，判定在 `bar_height`）:

| 档             | 逻辑像素 | 依据                                               |
| -------------- | -------- | -------------------------------------------------- |
| 胶囊           | **56**   | 窗口本身；胶囊 468×48，剩下的 8px 是发丝线和焦点环 |
| 主视图 / 音色  | **528**  | 卡片在 app 里封顶 520 + 同样的 8px 空气            |
| 简约（主视图） | **176**  | 只有头 + 时钟 + 传输条                             |
| 语速           | **188**  | 实测卡片要 178                                     |
| 定时关闭       | **312**  | 实测卡片要 301                                     |

`minimal`（设置 → 朗读 → 播放器样式 = 简约）**不是一档**：它改的是卡片**画什么**，不是它在哪个面板，所以只影响主视图那档，其他四档忽略它。

**窗口高度变了要守下边**（`resized_y`，`mini_bar.rs:181`）：贴底展开的窗口换高度时，上沿不动、底沿沿屏幕底边走，卡片才不会在读者已经看的那一行上跳。夹在工作区以内时改为**钉住上沿**（否则贴着 Dock 的屏会把它顶出去）。

**卡片切视图就把自己的视图名报给后端**（`onView` → `miniBarExpand(face, minimal)`），因为「webview 看不见自己所在的窗框」——新高度是前端知道的，卡窗的也是前端，只有中间那两个数（8px 空气、卡片封顶）后端也声明了一份。

**代价：每加一个视图要改三处**——`SpeechView`、`BarFace`、`bar_height`。而 `BarFace` 的命名**故意与 `SpeechView` 对齐**（外加一个 `Capsule`），就是为了让「前端报了一个卡片没有的视图」在类型上就不可能发生。改的时候别把名字改成两套词。

## 4. 合成钉在 rate 1.0

**决定**：`tts_edge_speak(text, voice)` — **没有 `rate` 参数**。SSML 的 `<prosody>` 只带 `pitch` / `volume`，不带 `rate`。倍速不进合成，也不进任何缓存键。

**为什么**：Edge 的一次合成是**按句**的（单次上限 1000 字，`MAX_TEXT_CHARS`），一次网络往返。倍速一变就让下一句重新合成，代价是一次往返 + 一次解码，而这两样都和「读者刚才想快一点」毫无关系。**切倍速应该是零成本的。**

**曾经不是**：`edge.ts` 的 `setRate` 走 `reconfigure()`，而 `reconfigure()` 做 `ready.clear() + inflight.clear()`——每次切倍速都主动把预取（`AHEAD = 2`）全丢掉。这才是「切倍速要重新加载」的根因，不是合成慢。

🔴 **真正的元凶在上层**：`useReadAloud.applySettings()` 原来**对倍速也**调 `restartSpeech()` → `play()` → `stop()` → 又是 `ready.clear()`。所以引擎层的优化被编排层完整绕过。现在是：

```ts
// useReadAloud.ts:491-496
if (change.voice === undefined) return; // 倍速不重启
```

**换音色仍然要重启**——两个引擎都把正在说的那个 clip 提交掉了，新音色只能靠新的一句话带过去。**重启的代价现在只为「换音色」付，而倍速不用付。**

**代价：新倍速落到下一句生效。** 这是当前设计唯一的用户可见的妥协（readest 同样如此）。想要「点了立刻变」需要 `retempo()`：同一 clip 按新倍速重拉伸、`source.start(when, offset)` 从当前位置续上、且**不动 `ready`**。难处在 offset 的换算（媒体时间 ÷ 倍速），不在拉伸本身——拉伸已经有 `stretched()` 了。

## 5. 变速在播放侧：WSOLA，不是 `playbackRate`

**决定**：`timeStretch.ts` 在**排程时**把解码好的 PCM 拉伸到当前倍速，再交给 Web Audio。`ready` 存**未拉伸**的解码结果，同一份解码在任何倍速下都能重放。

### 为什么不用 `playbackRate`

`AudioBufferSourceNode.playbackRate` 是纯重采样：2× 变花栗鼠，0.5× 发闷。媒体元素上的 `preservesPitch`（默认开）**在 buffer source 上不存在**。朗读是半小时以上的长时场景，这个退化很实在。

`preservesPitch` 唯一可用的是 `<audio>` 元素，而选 Web Audio 本身是有理由的（`edge.ts:14-20`）：`BufferSourceNode` 能**在精确时刻启动**并从 `ctx.currentTime` 读已播时间，而媒体元素只有 `timeupdate`——每秒四次，对着逐词高亮是可见的颗粒。换回 `<audio>` 等于重写播放核心。

### WSOLA 做了什么

把整段波形帧**按不同的间距重新铺开**：帧内基频周期长度不变，所以变的是速度而不是嗓音。每次拼接点选「与已写入尾巴最对齐」的位置（归一化互相关，±15 ms 搜索窗），重叠段线性交叉淡化以保持相位连续。参数是 SoundTouch 的语音默认值：**40 ms 帧 / 8 ms 重叠 / 15 ms 搜索**。

自己写的，没抄 readest（`services/tts/timeStretch.ts` 是它的，我们只核对参数与思路）。

### 词边界活在 rate-1.0 的媒体时间里

服务给的 `EdgeWord.at`（`offset / TICKS_PER_SECOND`，秒）是对着 **1.0× 的音频**量的。所以：

```ts
// edge.ts:301 —— 播放侧读回来时换算
const at = (ctx.currentTime - startedAt) * tempo;
```

漏掉这个 `* tempo` 的症状是：倍速越高，逐词高亮整体越早——**每一句都对，一整章都偏**。

### 代价：主线程上有一笔实测的开销

拉伸是**逐样本的算术，跑在主线程上**。用 demo 章节的真实散文（`speechUnits` 实切）量的：

| 倍速  | 最长一句（51 字） | 均值（10 句） |
| ----- | ----------------- | ------------- |
| 1.0×  | **0 ms**          | 0 ms          |
| 0.75× | 52 ms             | 31 ms         |
| 0.5×  | **77 ms**         | 46 ms         |
| 2.0×  | 20 ms             | 12 ms         |

`rate = 1` 在 `stretched()` 里直接返回原 buffer（`edge.ts:338`），所以**默认倍速零开销**。按秒音频算：0.5× 约 **75 ms/s**，2.0× 约 **19 ms/s**。

🔴 **所以「长句在 0.5× 下会不会卡一下」的答案是：会，但要 51 字才到 77 ms。** 真实中文散文 p50 是 **38 字**、p90 是 **51 字**（demo 章节实测），单句普遍在 20 ms 以内——一帧的预算之内。**触发它需要两样凑齐：0.5×（最慢档）+ 一个罕见的百字长句。**

想更稳的话，把拉伸挪进 Worker（`AudioBuffer` transferable）。**没做**：为了最坏情况的 77 ms 引入一个 Worker 和它的生命周期，代价大于收益——但这条「最坏 77 ms」是量出来的，不是猜的，所以将来若要动它，知道该盯哪里。

## 6. 其他已被消掉的「慢」

| 症状                    | 根因                                                  | 现状                                             |
| ----------------------- | ----------------------------------------------------- | ------------------------------------------------ |
| 切倍速要重新加载        | `reconfigure()` 清缓存 + `applySettings` 对倍速也重启 | §4                                               |
| 语音随页面离开而中断    | 玩家住在 `ReaderPage`                                 | §2                                               |
| 窗口一关就彻底没了      | 关闭 = 退出                                           | §3                                               |
| 胶囊贴着页脚 / 文字重叠 | 抬升量手量成 58px，CI 上页脚长到 78px                 | 改为 `ResizeObserver` 实测（`useElementHeight`） |

第四条值得单说：它**只在别人的机器上出现**。本地 macOS 页脚 57px，裸 `ubuntu-latest` 跑批机上 78px（没装中文字体，`rem` 被撑大），58px 的手写常量把胶囊仅剩的 20 px 净空吃到 8 px。**给「另一个宿主」的尺寸写死成常量，是这类 bug 的通用形状。**

## 7. 已知的坑（改这块之前先看）

- 🔴 **`AnimatePresence mode="wait"` 不要放在读者正伸手去够的控件上。** 它会等旧元素退场完（一个 exit 时长）才 mount 新的，头部那个「返回」按钮实测**双向滞后 200 ms**（封面还占着位子、然后箭头才弹出来）。要换就**当帧换**。换场动画留给「同一个控件的两个状态」（播放 ↔ 暂停）。
- 🔴 **motion 碰过的元素会被塞内联 `transform: none`**，压过 `press` utility 的 `:active` 缩放 ⇒ **有 press 的元素只做 `opacity`**，位移放到没有 press 的父行上。
- 🔴 **空容器在固定高度的宿主里会真的占地方。** 卡片的面板区在**任何**视图下都吃 `flex-1`；应用内卡片 hug 内容所以看不出来，悬浮条那扇窗口是 `h-full` 定高，于是空面板与音色列表**平分**了剩余空间（实测 186 px 空气 vs 186 px 列表）。修法是让 `flex-1` **有条件**。
- 🔴 **`-translate-y-*` 在 Tailwind v4 里设的是独立属性 `translate`**，所以 `transition-transform` 不会让它动——要过渡就写 `transition-[translate]`。
- 🔴 **写组件测试**：jsdom 有 `scrollIntoView` **没有 `scrollTo`**；`SpeechUnit.source` 是**数字**且必须给 `end`；`status: "playing"` 时播放键的可访问名是「**暂停**」；oxlint 的 `unicorn(consistent-function-scoping)` 连测试里的 helper 也会判错（要提到模块作用域）。
- 🔴 **e2e 里朗读 spec 假设「demo 章节比测试活得久」**，于是它在和时序赌，本地赢、CI 输。修法是装一个**永不结束**的语音引擎（`speak` 空实现）把那枚硬币拿走。
- 🔴 **别用「实验没红」当「假设被证伪」。** 曾经用「每句立刻 error 的敌意引擎」测出 8/8 通过就宣布「没有合成音」不是原因——实际那个引擎让队列**停滞**，会话同样不结束，症状同样消失。**该问的是「这个实验里目标现象真的被制造出来了吗」。**

## 8. 验证这个子系统

```bash
export PATH="$HOME/Library/pnpm/bin:$HOME/.cargo/bin:$PATH"

# 单元：含 WSOLA 的音高保持（5 条）
NODE_OPTIONS="" npx vitest run src/features/reader/timeStretch.test.ts

# 全量前端门禁（tsc + oxlint + vitest + build）
NODE_OPTIONS="" pnpm verify

# Rust 门禁；改过命令签名后必须重跑，它会重写 bindings.ts，跑完要 prettier
NODE_OPTIONS="" pnpm verify:rust && NODE_OPTIONS="" npx prettier --write src/lib/bindings.ts

# e2e（双引擎，跑 dist/）
NODE_OPTIONS="" pnpm build && NODE_OPTIONS="" npx playwright test
```

- **音高那条断言做过 sabotage**：把 WSOLA 换成朴素重采样 → 440 Hz 在 0.5× 下零交叉率偏 **50%**（正好是 440→220），红了。它是整个模块存在的理由。
- **e2e 里 `pill-timeline.spec.ts` 是一条会「说话」的诊断**：健康就绿，不健康才红，而且整条时间线（每次采样的存在 / y / 高度 / 播放状态 / 页脚高度）挂在失败消息里。胶囊为什么在动，它会答。

**真机要看的三件，量测代替不了**：

1. 2× 与 0.5× 的**听感**——WSOLA 不变调，但 2× 会略硬，这是物理极限不是 bug；
2. 逐词高亮在 1.5× / 2× 下**有没有漂**（`at` 乘了 tempo，但服务给的边界本身有误差）；
3. **最小化之后悬浮条是不是真的随后浮出来**（`bar_belongs` 认已最小化，但最多要等一个 400 ms 的 tick）。

## 9. 明确不做

| 不做                        | 为什么                                                             |
| --------------------------- | ------------------------------------------------------------------ |
| 把拉伸挪进 Worker           | 为最坏 77 ms 引入生命周期成本（§5 已量过这笔账）                   |
| `retempo()`（倍速立刻生效） | 会撤销「重启 = 扔缓存」这条设计的意义；要做就按 §4 的收尾算 offset |
| 系统语音也做 WSOLA          | `speechSynthesis` 不给原始采样，无从拉伸                           |
| 持久化朗读会话              | 队列按 `chapterIdx` 对齐，书籍重新导入后即失效（§2）               |
| 自建合成 / 自建云同步       | 项目红线                                                           |
